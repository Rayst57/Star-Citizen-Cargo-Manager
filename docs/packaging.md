# Windows Packaging — PyInstaller Bundle

Covers how to produce the distributable Windows build of Star Citizen Cargo
Manager.  Target: single-folder bundle zipped for distribution.  No installer
required for v1.

---

## Bundle strategy: one-folder (not one-file)

`--onefile` packs everything into a self-extracting archive that decompresses
to `%TEMP%` on every launch.  We use `--onedir` instead for three reasons:

1. **Startup time** — no extraction delay; DLLs are already on disk.
2. **Debugging** — user can inspect what's in the folder and attach a log.
3. **Partial updates** — a future patcher can overwrite individual files
   without rebuilding the full bundle.

The output folder is `dist/CargoManager/`.  Ship the contents of that folder
(not the folder itself) inside a zip: `StarCitizenCargoManager_v<VERSION>.zip`.

## Directory layout inside the bundle

```
CargoManager/
├── CargoManager.exe          ← entry point (generated by PyInstaller)
├── _internal/                ← PyInstaller's collected libs/modules (Python 3.12+)
│   ├── PySide6/              ← Qt6 DLLs, plugins, translations
│   ├── sounddevice/          ← PortAudio DLL lives here
│   ├── pvporcupine/          ← Porcupine shared library + keyword files
│   ├── pygame/               ← SDL2 DLLs
│   ├── openai/               ← OpenAI SDK
│   └── … (other collected packages)
├── data/                     ← bundled as data files (see spec below)
│   ├── schema.sql
│   ├── seed_stations.json
│   ├── seed_commodities.json
│   ├── seed_c2.json
│   ├── scu_boxes.json
│   └── ships.json
├── theme/
│   └── colors.json
└── cargo_manager.db          ← created on first run (NOT shipped in bundle)
```

> `docs/` is **not** included in the bundle.  They are developer/design
> references only.

## Database location

On first launch, `src/db/init_db.py` looks for `cargo_manager.db` next to the
executable (`sys.executable` parent for frozen builds; repo root for dev
runs).  If the file does not exist it is created and seeded automatically.

```python
import sys, pathlib

def _db_path() -> pathlib.Path:
    if getattr(sys, "frozen", False):          # PyInstaller frozen build
        base = pathlib.Path(sys.executable).parent
    else:                                      # dev / pytest
        base = pathlib.Path(__file__).resolve().parents[2]
    return base / "cargo_manager.db"
```

This keeps the database next to the `.exe` so users can easily back it up or
wipe it.  A future version may migrate to `%APPDATA%\StarCitizenCargoManager\`
for cleaner Windows-store compliance; defer until needed.

## Data file access in frozen builds

PyInstaller sets `sys._MEIPASS` to the bundle's `_internal/` directory (or the
temp extraction dir for one-file builds).  `data/` and `theme/` are collected
as datas and land at the same relative path under `_MEIPASS`.

Helper to resolve bundled assets:

```python
import sys, pathlib

def asset_path(relative: str) -> pathlib.Path:
    """Resolve a path to a bundled data file."""
    if getattr(sys, "frozen", False):
        base = pathlib.Path(sys._MEIPASS)
    else:
        base = pathlib.Path(__file__).resolve().parents[2]
    return base / relative
```

Usage:

```python
schema_sql = asset_path("data/schema.sql").read_text(encoding="utf-8")
colors     = asset_path("theme/colors.json")
```

## `.spec` file — `cargo_manager.spec`

```python
# cargo_manager.spec
# Generated from:
#   pyinstaller --name CargoManager --windowed --icon assets/icon.ico \
#               --collect-data pvporcupine --collect-data sounddevice \
#               src/main.py
# Then hand-edited to add datas and hidden imports.

block_cipher = None

a = Analysis(
    ["src/main.py"],
    pathex=[],
    binaries=[],
    datas=[
        ("data",  "data"),        # seed files and schema
        ("theme", "theme"),       # color palette
    ],
    hiddenimports=[
        "PySide6.QtSvg",          # QSvgRenderer used by some Qt themes
        "sounddevice",
        "pvporcupine",
        "keyring.backends.Windows",
        "pkg_resources.py2_warn",
    ],
    hookspath=[],
    hooksconfig={},
    runtime_hooks=[],
    excludes=[
        "tkinter",
        "matplotlib",
        "numpy",                  # not a direct dep; exclude if pulled in
    ],
    win_no_prefer_redirects=False,
    win_private_assemblies=False,
    cipher=block_cipher,
    noarchive=False,
)

pyz = PYZ(a.pure, a.zipped_data, cipher=block_cipher)

exe = EXE(
    pyz,
    a.scripts,
    [],
    exclude_binaries=True,
    name="CargoManager",
    debug=False,
    bootloader_ignore_signals=False,
    strip=False,
    upx=True,
    console=False,               # --windowed: no console window
    disable_windowed_traceback=False,
    target_arch=None,
    codesign_identity=None,
    entitlements_file=None,
    icon="assets/icon.ico",
    version="version_info.txt",  # Windows VERSIONINFO resource
)

coll = COLLECT(
    exe,
    a.binaries,
    a.zipfiles,
    a.datas,
    strip=False,
    upx=True,
    upx_exclude=[],
    name="CargoManager",
)
```

## Windows version info — `version_info.txt`

PyInstaller accepts a `version_info.txt` to embed Windows VERSIONINFO metadata
in the `.exe`.  Create / update this file before each release build.

```
VSVersionInfo(
  ffi=FixedFileInfo(
    filevers=(0, 1, 0, 0),
    prodvers=(0, 1, 0, 0),
    mask=0x3f,
    flags=0x0,
    OS=0x40004,
    fileType=0x1,
    subtype=0x0,
    date=(0, 0)
  ),
  kids=[
    StringFileInfo([
      StringTable(
        u'040904B0',
        [StringStruct(u'CompanyName',      u''),
         StringStruct(u'FileDescription',  u'Star Citizen Cargo Manager'),
         StringStruct(u'FileVersion',      u'0.1.0.0'),
         StringStruct(u'InternalName',     u'CargoManager'),
         StringStruct(u'LegalCopyright',   u''),
         StringStruct(u'OriginalFilename', u'CargoManager.exe'),
         StringStruct(u'ProductName',      u'Star Citizen Cargo Manager'),
         StringStruct(u'ProductVersion',   u'0.1.0.0')])
    ]),
    VarFileInfo([VarStruct(u'Translation', [0x0409, 1200])])
  ]
)
```

## Build procedure

Prerequisites: Python 3.12 on Windows, all `requirements.txt` deps installed,
`assets/icon.ico` present.

```bat
REM 1. Install deps (dev machine only; not in bundle)
pip install -r requirements.txt

REM 2. Run tests
pytest

REM 3. Build
pyinstaller cargo_manager.spec --clean

REM 4. Smoke-test the bundle
dist\CargoManager\CargoManager.exe

REM 5. Zip for distribution
powershell Compress-Archive -Path dist\CargoManager\* `
    -DestinationPath StarCitizenCargoManager_v0.1.0.zip -Force
```

`--clean` clears the PyInstaller `build/` cache so stale DLLs don't linger
between builds.

## Porcupine keyword file

The Porcupine wake-word engine requires a `.ppn` keyword model file
(platform-specific binary).  For v1 a built-in Porcupine keyword (`"hey
google"` or similar placeholder) is used because custom wake words require a
paid Picovoice training.

The keyword file path is stored in `AppSettings.porcupine_keyword_path` and
defaults to the bundled placeholder.  When the user upgrades to a custom
`hey-giant.ppn`:

1. They drop the `.ppn` file anywhere on disk.
2. Settings dialog → Voice → Keyword file → Browse.
3. App restarts voice subsystem with the new path (no recompile needed).

For the PyInstaller build, ship the placeholder `.ppn` as a data file:

```python
# In .spec datas list — add alongside data/ and theme/:
("pvporcupine/resources/keyword_files/windows/*.ppn", "pvporcupine/resources/keyword_files/windows"),
```

## UPX compression

The spec enables UPX (`upx=True`).  UPX reduces DLL size by ~30-50% but adds a
few seconds to launch on first run (decompression).  If launch time becomes
noticeable, set `upx=False` and accept the larger zip.

UPX must be installed separately and on `PATH`:
```
winget install upx.upx
```

## First-run experience

1. User unzips `StarCitizenCargoManager_v0.1.0.zip` to any folder.
2. Runs `CargoManager.exe`.
3. App detects no `cargo_manager.db` → creates and seeds it silently.
4. WorkdayScreen appears: "New Workday / Resume".
5. If no OpenAI API key is stored in Credential Manager, Settings dialog
   opens automatically prompting for the key (see `app_init_voice.md §5`).

No registry writes, no `%APPDATA%` writes, no UAC prompt.  The app is fully
portable — move the folder anywhere and it works.
